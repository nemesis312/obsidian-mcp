# obsidian-mcp v2 Roadmap

**Spec:** `docs/superpowers/specs/2026-10-30-memory-graph-design.md`

The spec spans several subsystems, so it ships as **six phases, one PR each**, merged into `develop` in order. After every phase, `develop` stays releasable: CI is green on all 3 OSes, and no tool is half-migrated. Only the first phase has a detailed task plan now. Each later phase gets its own plan once the previous one merges, so that plan is written against real interfaces instead of guessed ones.

| # | Phase | Spec sections | Depends on | Exit criteria |
|---|---|---|---|---|
| 1 | **Link resolver + live index**. One resolver with Obsidian rules. An in-memory index refreshed by a stat walk. Backlinks, outgoing, orphans and the graph all served from the index, with ghost nodes. The dead `Cache` is removed. | §7.1, §7.2 | — | The fixture vault passes every resolution case. `get_orphaned_notes` does zero file reads after the index is built. 5k-note benchmark numbers are recorded in the PR. |
| 2 | **Addressing, versions, cross-process guard.** Notes can be addressed by name (ambiguity errors list candidates, "did you mean"). Errors carry no absolute paths. Content-hash version tokens. Version is required for replace and delete. A cross-process write guard. | §6 (concurrency, write scope), §7.3 (addressing, optimistic concurrency) | 1 | A two-process race test on create, append and delete passes. A whole-note replace without a token is refused. |
| 3 | **Section edits + move/rename.** Replace, append and prepend under a heading. Moving or renaming a single `.md` note rewrites wikilinks, markdown links and frontmatter links, with dry-run and per-file failure reporting. | §7.3 (section edits, move/rename) | 1, 2 | Fixture round trip: after a move, every edge from phase 1 still resolves to the new path, and bytes outside the edited links are unchanged. |
| 4 | **Search + agent graph tools.** BM25 search with snippets, filters and pagination. `query_graph` (seeds, then BFS, then a token budget). Neighbors, shortest path and overview. Typed `relations` edges. The full graph dump is bounded. | §7.4, §7.6 | 1 | Every tool has a default limit and a hard cap (≤100 KB). Benchmarks hit the §8 budgets on 10k notes. |
| 5 | **Memory tools.** The memory schema; save with identity-based dedupe and additive updates; search memory; session context; lessons (computed on the fly, plus a marker-bounded materialize tool); `supersedes` lifecycle. | §7.5 | 2, 3, 4 | A two-process race on saving the same memory produces one note. Session context stays within budget and excludes resolved and superseded notes. |
| 6 | **v2.0.0 release.** Module path `/v2`. Final tool consolidation and a migration table. README, INSTALLATION and release notes with a "Breaking changes" section. Independent security review. Performance report. | §6 (module path, breaking changes), §7.7, §8 | 1–5 | The security review has no open Medium+ findings. `go install github.com/nemesis312/obsidian-mcp/v2/cmd/obsidian-mcp@latest` works from the tag. |

**Rule for every phase:** run an independent security review (a fresh reviewer, not the implementer) before merge on any phase that touches path handling or writes, which means phases 1, 2, 3, 5 and 6. In v1.x this review caught real bugs.
